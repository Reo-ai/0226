# Affiliate Pilot AI

## 1. アプリの概要

**AIアフィリエイト攻略司令塔**。アフィリエイト完全初心者（90日で月5万円を目指す）から、すでに集客できているSNS・ブログの運用者（初月5万円チャレンジ）までを対象に、「今日なにをすればいいか」を示し、学習・案件選び・コンテンツ制作・成果分析をひとつのアプリで進めます。

- PCで動かす、1人用のWebアプリです。スマホからは同じWi-Fi内で使えます
- 月額0円で使えます。AIは無料のローカルAI（Ollama）を優先し、AIがなくてもルールとテンプレートで主な機能が動きます
- 収益の達成を保証するものではありません。**発生報酬（承認前）・確定報酬（承認済み）・入金額**は分けて扱います

### 画面と機能

| 画面 | パス | 主な機能 |
|---|---|---|
| ダッシュボード | `/` | 今日やること（作業可能時間内）、目標と実績、ロードマップ、次のアクション、学習進捗 |
| 初期設定 | `/onboarding` | 経験・目標月収・期限・1日の作業時間・媒体・ジャンル・既存アカウント・月額予算 |
| ① AI司令塔 | `/coach` | タスクの優先順位付け、AIによる計画の組み直し、手動タスク、AIコーチ、週次振り返り |
| 90日ロードマップ | `/roadmap` | 4フェーズ×マイルストーン（データで自動判定、手動チェックも可） |
| ② アカウント | `/accounts` | ブログ・SNSの直近30日の数字（空欄は未計測） |
| ② 戦闘力診断 | `/accounts/assessment` | 集客力・反応・収益導線・案件適合・成約実績・データ信頼度、段階判定、優先改善3つ、評価基準の編集 |
| ③ 初月5万円チャレンジ | `/challenge` | 現状診断、逆算シミュレーター、30日プラン、必要数（計算）と実績の比較、承認時期の確認 |
| ④ 攻略大学 | `/academy` | 8講座・57レッスン。本文・具体例・注意事項・用語解説・チェックリスト・クイズ・実践課題・AIに質問・関連ツール・出典の確認状態 |
| ⑤ 案件分析 | `/offers` | 登録・編集・削除・検索・絞り込み・CSV入出力・適合性評価・計測リンク |
| ⑤ 案件比較 | `/offers/compare` | 同じ仮定での報酬シミュレーション、おすすめ理由・懸念点・確認項目 |
| ⑤ ASP一覧 | `/offers/asp` | 主要7ASPの特徴・登録の流れ・公式サイト・最終確認日 |
| ⑥ コンテンツ工房 | `/content` | 10種類の原稿、公開前チェック（PR表記・注意表現・ファクトチェック）、編集・コピー・Markdown出力・公開URL記録・動画化 |
| ⑦ 自動化センター | `/automation` | ジョブ（日次タスク・下書き・成果集計・改善案・週次レポート）、定期実行、実行ログ、エラー、キャンセル、再実行、定型文、投稿チェックリスト |
| ⑧ 収益分析 | `/analytics` | 日別・週別・月別・媒体別・案件別、CTR・CVR・承認率・目標達成率・作業時間分析、CSV入出力 |
| 設定 | `/settings` | AI接続（モデル選択・接続テスト・導入手順）、定期実行、バックアップ／復元、サンプルデータ |
- **サイト・SNSからおすすめ案件を提案**（`/offers/recommend`）: ブログ・YouTube・Instagram・X などのURLや貼り付けた投稿テキストからジャンルを判定し、合う案件の種類・探すASP・訴求の切り口・法規制の注意を提案。URLは公開ページをサーバー側で1回取得するだけ（SNSのスクレイピングやログインは行わない）。AI接続時は読者像と案件アイデアを追加。報酬額・承認率は表示しない（ASPで確認した値を登録して使う）。

Node.js を入れたあと、フォルダ内の **`起動.command`（Mac）** または **`起動.bat`（Windows）** をダブルクリックするだけで、パッケージの導入・データベースの準備・ビルド・起動・ブラウザを開くところまで自動で行います（初回は数分かかります）。ターミナルからは `npm run app` でも同じことができます。

## 6. SQLite の初期化 ／ 7. 初期データ投入


データベースを作り（マイグレーション）、攻略大学の8講座とASP 7社の情報を登録します。何度実行しても同じ結果になります。

## 11. ブラウザでのアクセス

http://localhost:3000 を開きます。初回は初期設定の画面が表示されます。

## 12. スマホからの接続方法

1. PCとスマホを同じWi-Fiにつなぎます
2. PCのIPアドレスを調べます（Windows: `ipconfig` の「IPv4 アドレス」、macOS: システム設定 → Wi-Fi → 詳細）
3. スマホのブラウザで `http://PCのIPアドレス:3000` を開きます
4. 計測リンクにもこのアドレスを使うなら、`.env` の `APP_BASE_URL` に同じURLを入れて再起動します

開けないときは、PCのファイアウォールでポート3000への接続を許可してください。

### 定期実行

アプリを起動している間、決まった時刻に自動でジョブを実行します（設定画面の「定期実行」で変更）。

- 毎日 7:00（既定）：今日のタスクを作る
- 毎週 月曜 8:00（既定）：週次レポートと改善案を作る（「確認待ち」で届き、承認すると提案に反映）
- PCを閉じていた日は、次に起動したときに1回だけ実行します。使い始めた週は週次ジョブを動かしません

### 画面の使い方

毎日の流れは「ダッシュボードの今日やることを進める → コンテンツ工房で作って自分で投稿する → 翌日、収益分析に数字を記録する」の3つです。画面右上の「?」（またはキーボードの `?`）で、この流れとキーボード操作の一覧が出ます。`g` のあとに `d`（ダッシュボード）`w`（工房）`a`（収益分析）などを押すと画面を移動できます。

## 15. トラブルシューティング

| 症状 | 対処 |
|---|---|
| `The table ... does not exist` | `npm run setup` を実行してください |
| `Port 3000 is in use` | 他のアプリを止めるか、`npm start -- -p 3001` で別のポートを使います |
| ヘッダーが「AIなし」のまま | Ollama が起動しているか確認し、設定画面の「接続テスト」を押します |
| 「モデル ◯◯ が見つかりません」 | `ollama pull ◯◯` を実行します |
| AIの生成が遅い・途中で止まる | 軽いモデル（`qwen2.5:3b`）に変えるか、設定の「応答を待つ時間」を延ばします。コンテンツ工房の「バックグラウンドで作る」を使うと、待つ間も他の画面を使え、自動化センターからキャンセルできます |
| AIの出力が形式エラーになる | 自動でルール・テンプレートに切り替わります。もう一度実行するか、大きいモデルを使ってください |
| スマホから開けない | 同じWi-Fiか、ファイアウォールでポート3000が許可されているかを確認します |
| `npm install` で Prisma のダウンロードに失敗する | ネットワークを確認して再実行します（社内プロキシ環境では `HTTPS_PROXY` の設定が必要な場合があります） |
| データを最初からやり直したい | `npm run db:reset`（すべてのデータが消えます。先にバックアップを） |

## 16. 無料運用の制約

- **AI**：ローカルAIの速さと文章の質はPCの性能に左右されます。性能が足りないPCでは「AIを使わない」設定にしても、ルール・テンプレート・手動入力で主な作業を続けられます
- **ASPの情報**：ASPには自由に使える公開APIがほとんどないため、案件や成果の数字は**手入力かCSVの貼り付け**で登録します。報酬額・承認率などは推測で埋めません
- **SNSへの投稿**：自動投稿はしません（各SNSの公式APIの審査・規約が必要なため）。コピーして手動で投稿し、公開URLを記録します
- **サーバー**：PCを起動している間だけ使えます。無料のクラウドホスティングではローカルAIは常時動きません

## 17. 将来の公開・SaaS化に必要な作業

- **認証とユーザー分離**：今は `lib/profile.ts` が最初のプロフィールを返す1人用です。ログイン機能を入れ、各データにユーザーIDを持たせて分離します（`APP_PASSWORD` は簡易的なパスワード保護のみ）
- **HTTPS と永続ストレージ**：公開サーバーでは HTTPS と、消えないデータベース（SQLite のファイル永続化、または PostgreSQL などへの移行）が必要です
- **AI**：公開サーバーではローカルAIが使えないため、クラウドAI（`ClaudeProvider` など）の利用料と利用制限の設計が必要です
- **権限管理・利用制限・課金管理**
- **SNS公式API**：`lib/publishing/adapters.ts` に公式APIのアダプターを追加します（各社の審査・規約に従う）
- **定期実行**：公開サーバーでは、アプリ内のスケジューラーの代わりに外部の定期実行（cron など）から呼び出す形にします

## データについて

- 金額は円の整数、CTR・CVR・承認率は 0〜1 の比率で保存します
- 未計測は NULL（0 と区別）。分母が 0 または未計測の率は計算しません
- 成果記録は「日付・媒体・アカウント・案件・公開」の組み合わせで1件にまとめ、二重集計を防ぎます
- 教材（`content/academy/*.ts`）は起動時に DB と同期します。学習進捗とクイズの結果は SQLite に保存されます

指示書の推奨構成とは、Next.js のルートグループ（`app/(app)/`）でサイドバー付きの画面をまとめた点、計算などを `lib/` 直下のファイルに分けた点が異なります。

## 設計メモ

- **AI**：`lib/ai` の `AIProvider`（`generateText` / `generateStructuredOutput` / `healthCheck`）を `OllamaProvider`・`ClaudeProvider`・`FallbackProvider` が実装します。戦略・案件分析・コンテンツ・分析・学習の役割はプロンプトで切り替え、共通ルール（実績の捏造禁止・最新条件を推測しない・架空レビュー禁止・実績と仮説の区別）を必ず付けます。出力は Zod で検証し、失敗したらエラー内容を表示してルールの結果に切り替えます。ユーザー入力や外部データは `<data>` で囲み、命令として扱いません。Ollama の接続先はローカル／LANのみ許可します
- **投稿**：`lib/publishing/adapters.ts`。初期版は手動投稿（コピー → 投稿 → URL記録）のみです
- **動画パイプライン連携**：コンテンツ工房の「動画にする」→ リポジトリ直下の `npm start -- hub-sync --loop 5` が取りに来て画像→動画を生成します（このアプリの `.env` に `PIPELINE_TOKEN`、リポジトリ直下の `.env` に `HUB_URL=http://localhost:3000` と同じ値の `HUB_TOKEN`）
